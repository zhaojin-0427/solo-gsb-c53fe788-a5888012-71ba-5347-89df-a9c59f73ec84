# 补偿工作流模型检验台

在浏览器中用**有向图**定义带补偿的工作流（活动、前置条件、可重试错误、最大尝试次数、
崩溃检查点、补偿动作），声明**“至多一次生效”“失败后最终撤销”**等不变量；系统在给定
步数上限内，枚举「成功 / 失败 / 重试 / 崩溃恢复 / 补偿」的全部交错，按**状态指纹**合并
等价分支。若不变量被破坏，返回按**轨迹长度最短、事件序稳定**选出的反例，并支持逐步回放、
在任意节点**修改结果后分叉对比**。

此外提供**随机故障风险分析**：为每个活动的成功 / 可重试错误 / 不可重试错误 / 确认前崩溃 /
确认后崩溃（应答丢失）以及补偿动作结果配置概率（同一调用分支、同一补偿分支的概率和均须为 1），
系统在选定步数上限内执行**带记忆的概率状态传播**：每个传播分支携带“该路径已首次违反过的
不变量集合”，按 **(状态指纹, 已命中集合)** 合并概率质量；不变量概率只在路径**首次命中**
（第一次进入违反状态）时累计一次，之后即使自定义不变量在多个后续可见事件中持续为假、
经循环恢复后再次为假，也不会重复计入；违反不是终态，持续违反的分支照常向前传播，
与结局分布正交。输出：

- **成功 / 补偿完成 / 补偿失败 / 边界截断**的概率分布；
- 各不变量被违反的概率（与结局分布正交，可重叠）；
- **补偿失败导致永久残留的期望未撤销效果数**（按效果键分解）；
- 贡献最大的**前 N 条事件轨迹**，可按概率/类别/步数排序，点击即复用同一套单步回放，
  并可从任意节点**跳转到现有分叉**继续有界检验；
- **明确标注边界截断**（截断概率、截断轨迹）与**概率校验错误**（分支和不为 1、未启用结果非零等）。

参数与分析结果（含前 N 条轨迹）保存在后端，可随时打开复现。

此外提供**并发调度安全分析**：活动可声明 **fork/join 汇合组**（fork 活动的每条生效出边
派生一个并发分支线程，全部分支到达 join 后汇合）以及对**共享资源**的读/写访问和按序获取的
**互斥锁**。检验器在给定步数内枚举可运行分支的**部分序交错**，按带**线程、锁、汇合令牌与
向量时钟**的状态指纹合并，识别三类问题并分别返回**按最短调度、稳定事件序**选择的见证轨迹、
涉及资源与阻塞原因：

- **数据竞态（data race）**：不同线程对同一资源的写-写 / 读-写访问之间不存在 happens-before
  关系、且不持有公共锁；用向量时钟判定（fork/join 汇合天然建立 HB，汇合后的访问不误报）；
- **锁顺序死锁（deadlock）**：分支间加锁顺序形成等待环，给出环上每个线程等待的锁与持有者；
- **无法汇合的分支（unjoinable）**：分两种情形严格区分——
  - **分支提前结束（问题判定）**：分支线程在到达本组 join 前**正常结束**（最后一条边通向
    区域内无出边的活动）时，汇合令牌在结构上永远无法交齐；在该分支结束的转移上立即生成
    `branch_ended_unjoinable` 事件并封存终态，给出提前结束的分支、停留活动、已到/缺失令牌数。
    该问题与步数边界无关：**任何足够大的步数边界下都必然检出**，见证按最短调度、稳定事件序
    物化，可单步回放并从见证节点分叉复现同一判定；
  - **步数不足（边界截断，不是问题）**：边界处仍有分支在运行、汇合组只是暂未闭合时，
    只在统计中列出边界处未闭合的汇合组并标记“到达步数边界”（`bound_reached`），
    **不会误报为“无法汇合”**，增大步数上限即可继续分析。

补偿（一个分支失败即释放全部分支持有的锁并进入全局 LIFO 补偿）、崩溃恢复与既有不变量在
并发语义下复用同一套规则；见证支持**逐步调度回放**（线程泳道、锁占用、汇合令牌、资源向量时钟）
与**从任意见证节点改选另一分支线程后续跑分叉**。模型与分析结果持久化，且**原检验与风险 API
完全兼容**（无汇合组声明的模型仍是纯串行语义）。

此外提供**版本行为对比**：选择两个**已保存模型**作为基线与候选、设置**同一步数上限**，
系统分别枚举两侧可达状态，按**稳定事件签名** `(类型, 活动, 尝试次数)` 逐一对齐轨迹：

- 对齐状态对按四类比较并分别给出**最短、可回放**的差异见证：**终态变化**（成功 / 补偿完成 /
  失败）、**变量变化**（新增 / 消失 / 取值不同）、**外部效果变化**（按效果键对比生效中 /
  已撤销 / 重复条数）、**不变量结论变化**（仅比较两侧共同启用的不变量；只在一侧启用的
  不变量单独列为配置差异，不误判为行为差异）；
- 某事件只在一侧可触发（如基线会失败、候选不会，或补偿动作开关不同）时产生**轨迹分叉**
  见证：触发侧真实执行该独有事件，另一侧在同一对齐步「保持」；**触发侧并不在此停止——
  会在剩余步数上限内、另一侧持留于分叉点的情况下，继续独立枚举该侧独有事件之后的全部
  可达状态**（按该侧状态指纹去重），因此独有事件**之后**才发生的应答丢失重调、
  `retry_timeout_duplicate` 重复生效、终态/变量/不变量变化都会进入报告，而不会只看
  独有事件的下一步就漏检；续跑差异见证给出从对齐前缀到差异成立状态的**完整单侧事件链**
  （首个为独有事件、其余标为续跑步，另一侧逐对齐步持留）；
- 见证是**双列对齐回放**：左右两栏分别展示基线与候选在每个对齐步的阶段/终态、活动、变量、
  外部效果与不变量，差异行高亮，独有事件步在另一栏标记「保持」；可在任意对齐节点对任意一侧
  **「改选并续跑」分叉复检**（复用既有有界 BFS 分叉接口与单步回放）；
- 搜索触及步数边界（或成对状态安全上限）时结论明确标注 **「结果未完备」**：有差异则判
  `差异（搜索未完备）`，无差异则判 `未发现差异但搜索未完备`，任何情况下都不声称两版本全局等价；
- 对比参数、**两个模型的完整快照**与报告一并持久化：即使事后删除/修改了模型，仍可打开
  记录复现并从差异节点分叉复检。对比使用与「有界检验」相同的串行转移语义（声明了 fork/join
  汇合组的模型在此不枚举部分序并发交错，报告会注明；并发行为差异请以并发分析为准）。

技术栈：Python 3.11 · FastAPI · SQLite · Z3（z3-solver）· 原生 JavaScript（无构建步骤）。
Docker Compose 一键启动后自动建表（含版本对比的 `diff_runs` 表），旧数据库升级无需迁移。

> ⚠️ 这是**有界模型检验**：结论只在“给定步数上限 + 给定交错模型”内成立。
> 搜索被截断时页面会明确标注“到达步数边界”，任何情况下都不会声称全局正确。

## 一、一键启动（Docker Compose）

```bash
docker compose up --build -d
```

启动后访问：

- 应用页面： <http://localhost:8000>
- 健康检查： <http://localhost:8000/api/health>
- 交互式 API 文档（FastAPI 自带）： <http://localhost:8000/docs>

停止：

```bash
docker compose down          # 保留数据卷
docker compose down -v       # 同时删除 SQLite 数据卷
```

SQLite 数据库保存在命名卷 `workbench-data`（容器内 `/data/workbench.db`）。
若本机 8000 端口被占用，修改 `docker-compose.yml` 中的端口映射即可。

## 二、本地开发运行（不使用 Docker）

需要 Python 3.11+：

```bash
cd backend
python -m pip install -r requirements.txt

# 前端为纯静态文件，通过环境变量告知后端目录
export CW_DB_PATH=/tmp/workbench.db

uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

然后访问 <http://localhost:8000>。

```bash
cd backend
python3 -m unittest discover -s tests
```

去重、最短反例、单步回放与节点分叉；`tests/test_risk.py` 覆盖随机故障风险分析的

确认前崩溃自环的截断概率、应答丢失 `p_ack/p_dup` 条件分裂与重复生效违反、
终态指纹经自环再达时的质量不重不漏、期望残留效果、前 N 轨迹排序与回放，以及
自定义不变量的“首次命中”传播：不变量在首个非终态事件后变为假并在随后多个

不同首次命中时刻的路径分别合并、违反后恢复再违反不重计、终态与边界截断
统计不重复追加、多不变量“任一违反”为路径并集，且分布始终守恒。
`tests/test_concurrency.py` 覆盖并发模块：fork/join 部分序交错枚举与线程/令牌
指纹合并、汇合只触发一次且续跑线程执行 join、稳定分支 tid、写-写/读-写数据竞态
的最短见证与同锁/HB 抑制误报、读读不冲突、相反加锁顺序死锁环与阻塞原因、
**分支在到达 join 前提前结束时在结束转移上封存“无法汇合”终态（任意步数边界
均可检出、见证最短可回放、从见证节点分叉复现同一判定）与步数不足只标记边界
截断不误报这一对相反回归**、分支失败释放全锁并全局 LIFO 补偿、分支内崩溃恢复与
重复生效不变量、汇合组/资源/锁的静态校验、调度回放与从见证节点分叉的 HTTP
端到端测试，以及无汇合组模型拒绝并发分析但既有检验/风险 API 不变的兼容性。
`tests/test_diff.py` 覆盖版本行为对比：同模型自比穷尽一致、事件只在一侧可触发的
最短轨迹分叉见证（分叉索引、触发侧独有事件、另一侧 hold 步与连续对齐索引）、

见证、只在一侧启用的不变量只进入配置差异、增长变量+环导致的边界截断标注

这一回归：基线无确认后崩溃、候选启用非幂等应答丢失时，独有恢复事件之后的重调

## 三、使用流程

1. 点击右上角 **「载入示例」**，推荐先选「电商下单（含超时重试与补偿）」。
2. 左侧按标签页编辑：
   - **活动与边**：活动节点（前置条件、外部效果键、幂等、失败/重试、最大尝试、崩溃检查点、
     补偿参数）、有向边（可选守卫）、起始活动；下方画布实时绘制有向图。
   - **变量**：声明 `int` / `bool` 变量与初值。
   - **不变量**：勾选内置不变量或编写自定义 Z3 表达式。
   - **JSON**：直接查看/编辑完整模型。
3. 点击 **「校验」**：检查图结构、表达式类型，并用 Z3 检查每个活动前置条件是否可能满足
   （恒为假的前置条件会被直接指出）。
4. 设置**步数上限**（1–80，默认 16），点击 **「开始检验」**。
5. 查看结论横幅：
   - `✗ 发现反例`：给出最短反例；
   - `✓ 边界内未违反`：已穷尽边界内全部状态；
   - `⚠ 到达步数边界`：搜索被截断，仅对边界内负责。
6. 在右下方**单步回放**（首/末步、单步、滑块、自动播放），每一步展示：
   - **持久状态**：每个活动的阶段（待执行/执行中/重试中/恢复中/成功/失败）、尝试次数、变量；
   - **外部效果与补偿栈**：生效中的效果、重复生效标记、LIFO 补偿栈、已撤销记录；
   - **触发规则**：本次事件、被跳过的边（守卫为假 / 前置不成立）、实际推进目标。
7. 在回放的**任意节点**，下方会列出该状态下所有可能的交错事件；点击非当前选择项即可
   **「改选并续跑」**，系统从分叉点重新做有界检验，并高亮共享前缀与分叉后缀，可在
   “原轨迹 / 分叉轨迹”之间切换对比。

## 三·五、随机故障风险分析

在右栏顶部切换到 **「随机风险分析」** 标签（左栏的 **「随机风险」** 标签页配置概率）。

### 配置概率

每个活动有两组独立分支（灰显 🔒 的结果表示该结果未在模型开关中启用，概率必须为 0）：

- **调用分支**（概率和必须为 1）：`成功` / `可重试错误` / `不可重试错误` /
  `确认前崩溃` / `确认后崩溃（应答丢失）`；
- **应答丢失条件**（仅启用 `post_crash` 的活动）：
  - `p_ack`：应答丢失后恢复时，查询确认“调用其实已生效”（`recover_acknowledged`）的概率；
  - `p_dup`：无法确认而重调、且重调成功时，“首次调用其实已生效”（造成重复）的条件概率；
- **补偿分支**（概率和必须为 1）：`补偿成功` / `补偿可重试错误` / `补偿不可重试失败`。

概率假设：**每次调用独立掷骰**。例如恢复（确认前崩溃后重新调用）或超时重调都沿用同一活动
的调用分支分布；`可重试错误`在最后一次尝试上按既有语义表现为「尝试次数耗尽」，权重不变。
工具栏可一键置为「均衡分布」或重置为「确定性成功」（等价于关闭全部故障开关）。

配置不当会在报告前以 **概率校验错误** 明确列出并阻止分析，例如：

- 某活动调用/补偿分支概率之和不等于 1；
- 给未启用的结果（如未勾选“应答丢失”却把 `post_crash` 配成非 0）配置了概率；
- 概率超出 `[0, 1]`、引用了不存在的活动或同一活动配置重复。

### 运行与报告

设置 **步数上限**（1–80，默认 24）与 **前 N 条轨迹**（1–50，默认 10）后点击「执行风险分析」。
报告包含：

1. **结局概率分布**：成功完成 / 补偿完成 / 补偿失败（效果永久残留）/ 边界截断；
   四类概率之和恒为 1（报告同时给出数值残差用于自检）；
2. **不变量违反概率**：每条启用的不变量单独给出；“任一违反”是路径并集
   （同一路径即使先后命中多条不变量、或同一条不变量在多个事件中持续为假，
   也只在**首次命中**的转移上计一次），与结局正交
   （例如非幂等活动超时重复生效时，轨迹结局仍是成功，但违反了“至多一次生效”）；
3. **期望未撤销效果**：补偿失败永久残留的期望条数，按效果键分解；截断部分携带的未撤销
   效果期望单独标注，提醒结论不完整；
4. **前 N 条事件轨迹**：默认按概率降序，可点击表头按 # / 概率 / 类别 / 步数排序；
   截断轨迹高亮标注步数。

### 轨迹回放与跳转到分叉

点击轨迹表中任意一行，即调用后端按该事件序列**逐步重放**，复用有界检验的同一套快照、
补偿栈与规则展示；在任意节点的「改选并续跑」会调用分叉接口（`risk/fork`，边界取风险
分析的步数上限），从该点继续**既有的有界 BFS 检验**并在“原轨迹 / 分叉轨迹”间对比——
风险分析与模型检验共享完全相同的事件空间与状态语义。

### 边界与截断声明

- 传播在**步数上限**处停止：仍未到达终态的概率质量计入「边界截断」，并列出代表性截断轨迹；
  状态空间超过安全上限（10 万指纹）时也会强制截断并标注。
- 崩溃/恢复等指纹自环会产生几何级数尾部；步数上限越大截断质量越小，但任何情况下报告都
  只对边界内负责，不外推全局结论。
- 每次分析的**参数**（各活动概率、`bound`、`top_n`）与完整结果都会持久化，右栏
  「风险分析记录」可一键打开复现；记录与模型绑定，删除模型时一并删除。

## 三·七、并发调度安全分析

在右栏顶部切换到 **「并发调度安全」**，左栏用 **「并发调度」** 标签页配置：

1. **fork/join 汇合组**：选择 fork 活动（至少 2 条生效出边）与 join 活动（必须从每个分支
   可达），并在下方活动注解里用单选标记 fork/join 角色。fork 成功后每条「守卫为真且前置成立」
   的出边派生一个分支线程；分支线程各自独立枚举成功/失败/重试/崩溃交错，全部到达 join 后
   合并向量时钟、由新的续跑线程执行 join 活动（join 只执行一次）。
2. **共享资源**：声明资源名，在活动注解里以逗号分隔标注「读资源 / 写资源」（同一活动对同一
   资源只需写）。
3. **互斥锁**：声明锁名，在活动注解里按**加锁顺序**逗号分隔标注；活动成功或失败后自动释放。
   允许分支边直接连到 join（该分支 fork 时即交令牌）；区域内不允许嵌套/重叠汇合组或成环。

设置**步数上限**（1–80，默认 24）后点击「并发调度安全分析」。可能的结论：

- `✗ 发现并发安全问题`：用类别页签切换 **数据竞态 / 锁顺序死锁 / 无法汇合的分支 / 不变量被
  破坏**，每张卡片给出**涉及资源（锁）**、冲突访问双方的线程/活动/持锁情况、**阻塞原因**，
  以及**按最短调度、稳定事件序**选出的见证轨迹；其中“无法汇合的分支”对应分支在汇合前提前
  结束（结构上永远缺令牌），在结束转移上封存；
- `✓ 边界内安全`：已穷尽边界内全部并发指纹状态；
- `⚠ 到达步数边界`：仍有未展开调度，仅对边界内负责。边界处只是“尚未闭合”的汇合组会在
  统计中列出（`pending_groups_at_bound`），属于步数不足导致的暂未闭合，**只标记边界截断、
  不产生“无法汇合”判定**；分支提前结束导致的真正无法汇合在任何步数边界下都会被检出。

**调度回放**复用单步组件：事件链上标注线程 id（分支线程为稳定的 `b_<组>_<出边序号>`，
不随调度顺序变化，便于精确重放与分叉）；快照区显示**线程泳道**（就绪/执行/加锁/阻塞/汇合）、
**锁占用表**、**汇合令牌**（已到/需要数）与**资源访问史**（每次访问的线程、向量时钟分量与
持锁集合）。在任意节点的备选事件里改选另一个分支线程的调度，即可**从该见证节点分叉**，
后端在新前缀下重新枚举并对比「原调度 / 分叉调度」。

**与既有语义的一致性**：

- 一个分支致命失败/重试耗尽 → 释放全部锁、撤销其余分支、进入**全局 LIFO 补偿**；
  无效果可补偿时为 `compensated`，补偿动作自身失败时为 `failed`；
- 确认前崩溃/应答丢失/歧义重试在分支线程内沿用同一状态机与「至多一次生效」判定；
- 自定义不变量（`succ/effects/undone`）在每个并发状态上求值，违反与上述三类问题并列报告。

内置示例「并发：双分支写同一账户（数据竞态）」与「并发：相反加锁顺序（锁顺序死锁）」
可直接载入体验。每次分析结果持久化在右栏「并发分析记录」中，可一键复现。

## 三·九、版本行为对比（基线 ⇄ 候选）

在右栏顶部切换到 **「版本行为对比」**。该模块对比的是**两个已保存模型**，因此请先用顶部
「保存模型」保存两个版本（载入示例后另存即可快速体验）。

1. 分别选择 **基线模型** 与 **候选模型**（不能相同），设置同一步数上限（1–80，默认 16），
   点击 **「执行版本对比」**。
2. 结论横幅四种：
   - `✗ 发现版本行为差异`：边界内已穷尽对齐搜索，并给出各类差异的最短见证；
   - `⚠ 发现差异（搜索未完备）`：已发现差异，但仍有轨迹在步数边界外未展开，可能还有遗漏；
   - `⚠ 未发现差异但搜索未完备`：边界内一致，但搜索被截断，**不能据此断言两版本相同**；
   - `✓ 边界内两版本行为一致`：已穷尽边界内全部对齐状态对，四类结论均无差异。
3. **差异见证页签**：`不变量结论变化 / 终态变化 / 外部效果变化 / 变量变化 / 轨迹分叉`
   各自给出最短对齐步数；卡片列出逐条变化（如「外部效果 eff：生效中 1→0」
   「不变量 X：基线被破坏，候选成立」）。
4. **双列对齐回放**：左右两栏分别是基线与候选，按相同事件签名逐对齐步展示；滑块 / 单步按钮
   同步两侧；分叉步触发侧显示独有事件、另一侧标记「⏸ 保持」；若差异在独有事件**之后的
   单侧续跑**中才成立，触发侧继续显示续跑事件链，另一侧的后续步标记「持留（另一侧续跑中）」，
   差异在续跑末步高亮；底部实时列出当前对齐步的全部差异。
5. **从差异节点分叉复检**：双列每一栏的「在该节点改选并续跑」列出该侧当前可触发的全部事件，
   点击非当前选择项即调用 `/api/diff/fork`，在**该侧模型**上沿对齐前缀续跑既有有界 BFS，
   复检结果以与「有界检验」完全相同的单模型轨迹/快照展示（仍可继续再分叉），可一键返回双列见证。
6. **持久化与记录**：每次对比的参数（两侧模型 id/名称、bound）、**两侧模型完整快照**与报告
   都保存在右栏「版本对比记录」；点击记录即按快照重新打开——即使原模型后来被删除或修改，
   见证回放与分叉复检仍可复现。

内置示例 **「版本对比·基线（支付不重试，失败即补偿）」** 与
**「版本对比·候选（支付可重试，记录重试次数）」** 可分别保存后直接对比体验：
候选多出可重试错误与重试交错（轨迹分叉），出凭证后的变量取值也不同。

**边界约定**：版本对比与「有界检验」共用同一套串行转移系统与稳定事件签名，
对齐展开按 `(基线指纹, 候选指纹)` 去重；每条单侧独有事件触发后，在**同一个步数上限**
内（对齐深度 + 单侧续跑步数不超过 `bound`）按该侧状态指纹去重继续枚举，对齐状态对与
全部单侧续跑状态合计超过 20 万安全上限时强制截断并标注未完备。只要某条单侧续跑在步数
边界处仍有未展开状态，结论同样是 `差异（搜索未完备）/ 未发现差异但搜索未完备`，
任何情况下都不会把独有事件后续未枚举的分支当作「搜索已完备」。声明了 fork/join 汇合组
的模型在此**只按串行结构**枚举，不枚举部分序并发交错（报告与每条记录中都有该语义提示）。

## 四、模型语义

### 4.1 活动（节点）

| 字段 | 含义 |
| --- | --- |
| `pre` | 前置条件：活动被选为后继时必须成立（布尔表达式） |
| `effect` | 外部效果键；活动成功时登记一条“已生效”记录，失败后按 LIFO 补偿 |
| `idempotent` | 幂等：超时重调后即使首次其实已生效，也与重试合并为同一逻辑效果 |
| `can_fail` | 活动是否可能失败（关闭后调用总是成功，用于建模确定性操作） |
| `retryable` | 失败是否可重试；可重试错误会持久化并确定性地重新入队 |
| `max_attempts` | 最大尝试次数（含首次，`1` = 不重试）；用尽即放弃并进入补偿 |
| `pre_crash` | **确认前崩溃**检查点：无任何持久痕迹，崩溃后活动进入显式的**「恢复中」**状态，恢复时重新调用同一活动（不增加尝试次数、不产生外部效果） |
| `post_crash` | **应答丢失/超时**检查点：恢复时可能（a）查询确认已生效，或（b）无法确认而重调；重调成功时分叉为“首次其实已生效→重复”与“首次未生效→干净” |
| `assign` | 成功后的变量赋值（可引用本次效果计数） |
| `comp_can_fail` | 补偿动作是否可能失败（关闭=补偿总是成功） |
| `comp_retryable` / `comp_max_attempts` | 补偿动作的可重试性与最大尝试次数 |
| `fork_group` / `join_group` | （并发）该活动是某汇合组的 fork 分叉点 / join 汇合点；通常在 `concurrency.groups` 中声明，活动字段自动标注 |
| `reads` / `writes` | （并发）成功时对共享资源的读 / 写访问名列表（字符串数组） |
| `locks` | （并发）进入活动时按序获取、成功/失败后自动释放的互斥锁名列表 |

模型顶层可选的 `concurrency` 段：

```json
"concurrency": {
  "resources": [{"name": "accountBalance"}],
  "locks": [{"name": "accountLock"}],
  "groups": [{"id": "pay", "fork": "forkPay", "join": "joinPay"}]
}
```

不声明 `groups` 即纯串行模型；新增字段全部可选，旧模型无需改动。

### 4.2 边与选择顺序

- 出边按**声明顺序**检查，选择第一条“守卫为真 **且** 目标活动前置条件成立”的边；
- 被跳过的边会在回放中标注原因（`guard_false` / `precondition_false`）；
- 没有出边 → 工作流正常成功完成；
- 有出边但没有可选后继 → 正向流程失败，转入补偿；
- 边可成环：回到旧活动时重置其尝试计数，因此检验必须设置步数边界。

### 4.3 交错事件（每个活动被调用时枚举）

- `success` 成功（效果生效、执行赋值、沿边推进）；
- `retryable_error` → `retry` 可重试错误并确定性重调；
- `fatal_error` 不可重试错误，立即补偿；`attempts_exhausted` 重试耗尽；
- `crash_before_ack` 确认前崩溃：进入可区分的**恢复中**状态（与崩溃前业务字段相同也不会被指纹去重丢弃）；
- `recover_pre_ack` 崩溃恢复：确定性地**重新调用同一活动**，尝试次数不增加、无外部效果；恢复后成功、失败、再次崩溃的交错重新全部展开；
- `recover_acknowledged` 应答丢失后查询确认“其实已生效”；
- 超时重调后：`retry_timeout_duplicate`（首次也生效→**重复**）/
  `retry_timeout_clean`（首次未生效）；
- 补偿阶段：`compensated` / `comp_retryable_error` → `comp_retry` /
  `comp_fatal_error` / `comp_attempts_exhausted`。

确定性的中间动作（错误持久化后重新入队、ε 转移）不产生额外反例步长。

并发调度分析在上述事件之外还有调度事件：`thread_schedule`（选中就绪分支）、
`lock_acquired` / `lock_wait`（获得锁 / 等待锁，后者形成等待环时即死锁）、
成功事件上的 `fork_group`+`branches`（fork 派生）、`join_arrive`（分支到汇合点交令牌）、
`join_fire`（令牌齐汇合、新建续跑线程）、`branch_ended_unjoinable`（分支在到达 join 前
正常结束、汇合令牌永远无法交齐：封存为“无法汇合”终态，与步数边界无关）。
分支线程 id 形如 `b_<组id>_<出边序号>`。

### 4.4 不变量

| 不变量 | 何时被判定破坏 |
| --- | --- |
| **至多一次生效**（可开关） | 非幂等活动因超时/应答丢失重试，导致同一效果键存在两条“未撤销”的生效记录 |
| **失败后最终撤销**（可开关） | 终态为 `failed`，且仍有外部效果未撤销（包括补偿动作自身失败或重试耗尽） |
| **自定义** | 任意布尔表达式在某个可达状态为假 |

### 4.5 状态指纹与最短反例

指纹包含：运行阶段、各活动状态（含**恢复中**状态：即使其变量/尝试次数/外部效果
与崩溃前完全相同，也作为独立指纹参与去重，不会被错误合并）与尝试次数、变量取值、
外部效果序列（含撤销/重复标记）、LIFO 补偿栈与补偿尝试次数、终态。指纹相同的分支
只展开一次。因此「崩溃 → 恢复 → 回到原活动」形成的自环在有界 BFS 中天然收敛，
而崩溃态本身、恢复事件仍完整参与最短反例、单步回放与节点分叉。

BFS 逐层展开、同层按事件签名 `(类型, 活动, 尝试次数)` 排序，因此第一次命中的违反保证是：

1. **轨迹长度最短**；
2. 长度相同的反例中**事件序字典序最小**（稳定可复现）。

## 五、表达式语言（Z3）

```
expr   := or
or     := and ('or' and)*
and    := not ('and' not)*
not    := 'not' not | cmp
cmp    := arith (('=' | '!=' | '<' | '<=' | '>' | '>=') arith)?
arith  := term (('+' | '-') term)*
term   := factor (('*' | '/' | '%') factor)*
factor := '-' factor | 数字 | 'true' | 'false' | 标识符 [ '(' 字符串 ')' ] | '(' expr ')'
```

内置计数函数（可用于前置条件、边守卫、自定义不变量、赋值右侧）：

| 函数 | 含义 |
| --- | --- |
| `succ("活动id")` | 该活动成功次数 |
| `effects("效果键")` | 该效果当前**仍生效**（未撤销）的次数 |
| `undone("效果键")` | 该效果已被补偿撤销的次数 |

示例：

```text
effects("accountCharged") <= 1                 # 扣款至多生效一次
effects("shipNotified") = 0 or effects("accountCharged") > 0   # 发货前必须已扣款
succ("a") > 0 and not vip                      # a 成功过且当前不是 VIP
x + 1                                          # 赋值表达式
```

前置条件在模型编译时会用 Z3 做一次**可满足性检查**：若计数符号取任意非负值都无法满足
（例如 `effects("x") < 0`），判定该活动永远不可启用并阻止保存。

## 八、检验边界声明（重要）

- “✓ 边界内未违反 / 已穷尽”只表示：在**声明的步数上限内**、按**当前勾选的失败与崩溃
  交错模型**，所有可达状态均满足不变量；
- “⚠ 到达步数边界”表示仍有未展开分支，增大步数上限可能得到不同结论；
- 关闭某活动的“可能失败 / 应答丢失”等开关，等于显式假设该操作不会发生对应故障，
  结论依赖这些假设本身；
- 工具不会、也不应输出“模型全局正确”这类超出检验边界的断言。
